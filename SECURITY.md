# Security Policy

## Reporting a vulnerability

If you believe you have found a security issue in QuietClaw:

- Use GitHub's private vulnerability reporting or GitHub Security Advisories for this repository if that option is available.
- If private reporting is not available, open a GitHub issue with a minimal description of the problem and enough context for triage, but do not publish secrets, private data, credentials, exploit code, or full reproduction details until a maintainer asks for them.
- For non-sensitive security hardening suggestions, opening a normal GitHub issue is fine.

## What to include

- A short description of the issue and affected area.
- The version, commit, platform, or environment involved.
- Clear reproduction steps, proof of concept, or impact description, shared privately when appropriate.
- Any suggested remediation or mitigation, if known.

## Expectations

- This repository does not offer a bug bounty program, paid support, guaranteed response time, guaranteed remediation timeline, or any commitment to fix every reported issue.
- Reports are handled on a best-effort basis.
- Submitting a report does not create any obligation to respond, disclose, patch, or release on any schedule.

## Scope

Please report suspected vulnerabilities in this repository's code or documentation. Do not use public issues for credentials, secrets, or other sensitive material.
